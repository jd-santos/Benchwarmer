# Benchwarmer workbench

Benchwarmer helps its single user understand work done across agent tools and
choose an acceptable model, reasoning level, harness, and configuration for each
kind of task. Conversation history, usage, cost, quality evidence, and eventually
repeatable trials support that choice. The first useful experience is a clear
way to navigate and report on real history before building automated grouping
and judged experiments. This workbench tracks that path. It follows the
[`todo-manager`](https://github.com/jd-santos/Skills/tree/main/skills/todo-manager)
workflow from [jd-santos/Skills](https://github.com/jd-santos/Skills).

- [TODO](TODO.md) is the single live P1–P5 priority index.
- [`work/`](work/) gives substantial efforts a stable home. Each README owns its
  detailed checklist, execution status, dependencies, acceptance, and handoff.
- [DONE](DONE.md) points to Git history and retained evidence, without keeping
  another completed-task ledger.
- [The roadmap](../docs/roadmap.md) explains delivery order; maintained design
  documents own architecture and product rules.

## Priorities

P1 means immediate interruption, P2 is important next work, P3 is required work
without immediate urgency, P4 is useful later work, and P5 is optional polish.
Priority does not indicate execution status or waive prerequisites. Task names
are descriptive; folder links provide stable identity without task codes.

## Following work

Start with the priority index, then read the selected work record and its links.
Keep small tasks inline and larger work in descriptive folders. Completed
checkboxes stay in place until reviewed shipping closeout. Git and retained
records preserve the finished story. A plan or checked box does not prove merge,
release, deployment, or passing tests.
