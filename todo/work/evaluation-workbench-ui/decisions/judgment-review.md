## Question

How should the user compare candidate outputs and artifacts, inspect each applied
judge's evidence and reasoning, add human review, and resolve disagreement without
turning unjudged or uncertain outcomes into failures?

Prototype task-first and configuration-first comparison, criterion-level results,
side-by-side source and output inspection, repetitions, failures, judge errors,
inapplicability, uncertainty, human corrections, calibration evidence, and links
back to motivating bundles. Keep quality, tokens, money, speed, and judge overhead
separate while still supporting practical comparison across the same task set and
distinct source-lineage families.
