# Define evaluation-project navigation and artifact relationships

Type: Grilling, human in the loop\
Status: Open\
Claim: Unclaimed\
Parent: [Design the evidence-to-evaluation workbench UI](../README.md)\
Blocks: [Design test-plan authoring and applied-judge preview](test-plan-authoring.md)

## Question

How should a user move between the global conversation library and an optional
evaluation project without losing the evidence trail or forcing project creation
for ordinary review?

Define the project's visible relationship to its question, live collections,
frozen datasets, evidence bundles, task drafts and versions, test plans, runs,
and results. Decide what establishes current project context, how artifacts can
belong to or be referenced by more than one project, how global search and saved
views enter a project workflow, and how the interface keeps location, version,
selection, and unsaved changes clear.
